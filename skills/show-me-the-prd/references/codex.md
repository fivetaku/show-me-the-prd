# Codex에서 실행할 때 (show-me-the-prd)

SKILL.md 절차는 그대로 따르고, 아래 차이만 적용한다.

## 카드 질문 = 질문 도구 (이번 세션 도구 목록으로 판단)

1. `request_user_input_async`가 있으면 카드 1콜 = 이 도구 1콜. 문항 ≤4개를 한 번에 넣는다.
   - 형식: `{"questions":[{"title":"헤더 — 한 줄 질문","options":["라벨 (추천) — 뭔지, 장점, 단점","대안 — 뭔지, 트레이드오프"]}]}`
   - 문항에는 `title`·`options`만. `question`·`header`·`id`를 넣으면 파싱 오류가 난다.
   - 추천안을 맨 앞에(기본 선택). "기타·직접 적기" 옵션은 넣지 않는다(자유 입력 칸이 자동으로 붙는다).
   - 부른 뒤 "위 질문에 답해 주시면 이어서 진행합니다" 한 줄만 쓰고 **턴을 끝낸다.** 답은 다음 사용자 메시지로 온다. 답에 달린 결정을 추측으로 진행하지 않는다.
2. Plan 모드라 `request_user_input`만 있으면: 1콜 3문항까지라 4문항 카드는 두 번에 나눈다. `header`(12자 이내)·`id`(snake_case)·`question`, 선택지 2~3개(`label`·`description`), 추천 라벨 끝에 `(Recommended)`.
3. 둘 다 없으면 채팅에 번호 블록으로 낸다:

```text
Q1. <한 줄 질문>
  1. <추천안> (추천) — 무엇인지, 왜 좋은지, 트레이드오프
  2. <대안> — 무엇인지, 트레이드오프
  3. 문장으로 직접 적기
(답은 "Q1-1, Q2-2"처럼. 모르면 전부 1번으로 진행할게요)
```

4. `codex exec`처럼 사람이 답할 수 없는 실행이면 묻지 않고 추천안(기본값)으로 진행하고 가정 원장에 기록한다.

## 프리뷰

질문 도구는 프리뷰를 띄우지 못한다. 기술 스택 비교표·데이터 모델 관계도·Phase 표는 도구를 부르기 **직전 채팅 메시지**에 짧게 먼저 보여준다. 채팅에서는 마크다운 표 대신 짧은 목록이나 ASCII를 쓴다(생성하는 문서 안의 표는 템플릿대로).

## 그 밖의 차이

- 첫 실행 설정(`setup/setup.sh`)은 Claude Code 전용이다. Codex에서는 실행하지 않는다.
- 다음 단계 안내의 goaljaby는 Codex의 goaljaby 스킬로 넘긴다(승인하면 그 스킬이 `create_goal`로 골을 시작한다).
